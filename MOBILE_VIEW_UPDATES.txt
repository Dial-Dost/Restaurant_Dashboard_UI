1. DASHBOARD NAVIGATION ON PHONES (the main fix)
------------------------------------------------
Problem: the only dashboard navigation was a macOS-style Dock. For an admin it
holds 22 icons and is about 1,364px wide, so on a 375px phone it runs off both
edges. Its labels also only appear on hover, and touch screens have no hover.

[x] New bottom navigation bar for phones
    - Fixed bar at the bottom of the screen with 4 main destinations plus a
      "More" button.
    - Labels are always visible under the icons.
    - Links use the same permission-filtered list as the Dock, so the two
      can't get out of sync.
    Files: src/components/mobile-nav.tsx, src/app/dashboard/layout.tsx

[x] The 4 bar slots are picked on purpose, not just the first 4 items
    - Priority order: Orders, Tables, Menu, Dashboard.
    - Floor plan is not on the bar (nobody opens it during service). Menu is
      (dishes get marked unavailable during a rush).
    - Short navs (waiter-only, valet) get a short bar and no empty "More".
    - Rule: every destination is either on the bar or in "More". None dropped.
    File: src/lib/mobile-nav-layout.ts

[x] "More" bottom sheet
    - Slides up from the bottom and holds every other page, grouped under the
      same section titles as the Dock.
    - 3-column grid of large tiles (4 columns from sm), up to 80% of the
      screen height, closes when you tap a link.

[x] Thumb-sized tap targets
    - Bar buttons are at least 56px tall and icons are shrunk slightly so the
      labels fit.

[x] Safe-area padding
    - The bar adds env(safe-area-inset-bottom) so it clears the iPhone home
      indicator.

[x] Dock only shows where it fits
    - The Dock is hidden below 2xl (1536px) and the bottom bar shows instead.
      That covers phones, tablets and 1280px laptops, where the Dock was also
      measured overflowing.

[x] Page content no longer hidden behind the bar
    - Main content bottom padding is 80px below 2xl and 96px from 2xl.
    - Fixed a bug where the "p-" shorthand overrode the bottom padding at lg,
      so the bar covered the last card on every page.

7. OPENING THE APP ON A PHONE, AND THE ANDROID APP
--------------------------------------------------
[x] Guest pages work when opened on a phone
    - Guest pages call the backend through a same-origin "/backend-api"
      proxy.
    - Before this, a phone that opened the page by LAN IP or tunnel tried to
      reach "localhost" (the phone itself) and the page came up blank.
    - A production build with no backend URL also sent QR-code scans to a
      404 page; that is fixed too.
    Files: next.config.ts, src/lib/backend-url.ts, src/lib/guest-backend.ts,
           Dockerfile, .github/workflows/deploy.yml

[x] Dev server accepts phones on the LAN IP or a Cloudflare tunnel
    - Uses the allowedDevOrigins setting.
    File: next.config.ts

[x] Android APK download
    - public/downloads/RestaurantDash-Android.apk is served at /downloads.
    - It is kept out of the Docker image and mounted read-only on the server.
    - The deploy check fails if that exclusion is removed.
    Files: .dockerignore, deploy/README.md, .github/workflows/deploy.yml

9. KNOWN GAPS / POSSIBLE NEXT STEPS
-----------------------------------
[ ] No "viewport" export with viewportFit: "cover" in src/app/layout.tsx.
    Without it, env(safe-area-inset-bottom) is usually 0 in a normal browser
    tab, so the bottom bar's safe-area padding may not do anything yet.
[ ] Content bottom padding is a fixed 80px and doesn't include the safe-area
    inset. On a phone with a real inset, the bar may be taller than the
    padding.
[ ] The 16px anti-zoom rule for select and textarea can lose to a Tailwind
    text-* class set directly on those elements.
[ ] Platform admin login (src/app/platform/login) still uses min-h-screen
    instead of min-h-dvh.
[ ] No web app manifest or theme colour. The APK is not built from this repo
    (no Capacitor or PWA setup).
[ ] Deploy docs list the APK as about 94 MB and the zip as about 16 MB. The
    files on disk are about 57 MB and 18 MB.
[ ] src/components/ui/sidebar.tsx (shadcn, with its own mobile sheet mode)
    isn't used anywhere.
